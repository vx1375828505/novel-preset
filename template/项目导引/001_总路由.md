# 00_总路由（唯一入口 · 开工就照这个走）

> 【文件卡】作用=全项目唯一开工入口：读什么、走哪张卡、交什么，全写在这一页｜何时用=任何任务开始（新会话、换平台、换 Agent 都一样）｜上游=无｜下游=`项目中枢/006_进度.md` + `项目中枢/文章精修规则/061_规则调用路由.md`（专项按轮选择）｜不做的事=不列文件清单、不写细则、不设层
>
> **一句话：开工只读两样；精修交付两件套，写新章四件；红项不清零不交稿。**

## 一、开工入口（一轮一规则）

1. 读 **`项目中枢/006_进度.md`** 的 S0-S2：当前断点、冻结项、质量基线。
2. 精修、改稿、检查、验收或交付：读 **`项目中枢/文章精修规则/061_规则调用路由.md`**，按本轮唯一主问题选一份062—083专项规则。
3. 路由只负责选规则；**每轮只执行一份专项，其他问题留下一轮**。连续施工也按一轮一份拆分。
4. 写新章 → `项目中枢/写文规则/012_场景卡_写新章.md`。
5. 用户只问“项目什么情况” → `项目导引/002_全局记忆.md` + `项目导引/003_项目目录.md`，读完确认要做什么。

## 二、交付固定两件套（2026-11-19 用户拍板）

1. **优化后稿页**：整章可直接读。
2. **对照页**：原件 → 优化稿（红删绿增）。生成命令：`python3 tools/make_diff.py 基线.txt 优化稿.txt --title "标题" --out 输出.html`

> 写新章仍按四件：稿子 / 对照页 / P3 数值 / 改动清单。

**红线：P3 有红项，先改到清零再给用户看。P3/P4 数值只进内部留档，不另交。**
**AI 产出未拍板 = 草稿；没拍板不动正文、不进下一章。**

## 三、单类规则调用（2026-11-20 用户拍板）

> **一轮只执行一份专项规则（精修场景）。**061负责选择，062—083各自只回答一个问题。
> **例外（2026-11-23 用户拍板）**：写新章/新段落/整段重写走 `项目中枢/写文规则/012_场景卡_写新章.md` §4.5 四维命中自检，四维一次性同时过，不适用一轮一规则；062—083 的专项规则作为命中后各维的深修工具。

1. 先确认本轮唯一主问题；多个问题列轮次，不混跑。
2. 按061索引选一份专项，只读取并执行该文件。
3. 发现其他问题，只记入后续项，不展开另一份规则。
4. 分析、修改、082验收、083交付都可分别独立成轮。
5. 用户要求连续施工时，仍逐轮完成，直到用户指定范围结束。
6. 规则冲突时以用户最新拍板为先；无明确裁决则停下确认。

专项目录见 `项目中枢/文章精修规则/000__子路由.md`。参考手法、桥段与判例是素材，不代替专项规则。

## 四、文件编号（2026-11-19 起）

- 活跃文档文件名 = `NNN_名称.md`，`NNN` 是全库连续序号，从 `001` 起，一直往下排。
- 每个文件夹的门牌 = `000__子路由.md`，不占全局号。
- 旧 `【序号】000-118` 只保留在文件卡里作历史引用，不再维护全量编号表。
- 找文件：直接看文件名，或进夹读 `000__子路由.md`。
- 正文（`第NNN章`）、草稿、参考资料、退役归档不参与此编号。
- 支线已并入 `核心资料库/支线/`，随全库连续编号。

## 七、规则冲突裁决（谁压谁）

一个文件只答一个问题；答不了的用指针。真撞车时按下面裁决，不自己发明：

1. **用户拍板 > 一切规则。**
2. **字数硬门禁（L1_01）> 其他数值**：超 3000 必砍，不拿“朗读顺”当借口。
3. **朗读顺口（080）> 中位数值（082）**：中位只统计叙述句，不为凑数字塞转述。
4. **长句口径**：082统计“整句（含逗号）”；080判断“单口气与语义断点”，两个单位不混用。
5. **人设（067）> 笑点密度（081）**：笑点不许以压平男主为代价。
6. **同一规则只在一个文件有全文**：归口文件内指针只做指路，不复制全文；报告正文不写数值，P3/P4 数值单列“内部留档”。
7. 仍无解 → 问用户，不自己发明新规则。
