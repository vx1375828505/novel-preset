# 小说项目库操作系统（novel-project）

把一套经 104 章实战验证的写作库方法论装进 App：**开新书自动生成整套库，日常按库的规矩读写维护**。
完整骨架在 `template/`，工具脚本在 `scripts/`。

> **路径约定**：本技能安装后位于 `/var/minis/skills/novel-project/`。下文所有 `template/` = `/var/minis/skills/novel-project/template/`，`scripts/` = `/var/minis/skills/novel-project/scripts/`。复制或执行脚本时用绝对路径。

## 零、四条不可违反的铁律

1. **已有库只读**：用户的现有小说库（如 `/var/minis/mounts/小说/小说项目`）未经明确点头，一个字都不能改。只读、只引用。
2. **先问再动**：任何建库、写正文、改规则、动结构的动作，先用 `user_ask`（confirm）拿批准；没批准就停，返回"已取消"。
   **confirm 的问题文本必须写出完整落盘路径**，例如「将写入 `/var/minis/mounts/小说/我的书/正文/第001章：开端.txt`，是否继续？」。代码层有写前确认硬门，它按「批准文本里是否包含目标路径」来放行——只写「要写第001章吗」而不写路径，批了也写不进去。
3. **一轮只做一件事**：按 061 路由选**一份**规则执行，发现别的问题只记入"后续轮次"，不顺手做。
4. **没拍板 = 草稿**：AI 产出未经用户逐项确认，不得覆盖正文、不得推进下一章。

## 一、开新书（生成整套库）

用户说"开新书 / 新建小说项目"时：

1. **收集信息**（`user_ask` 一次问全）：书名、流派/类型、平台、男主名、主要角色名。
2. **出清单**：列出将创建的 9 个目录 + 关键文件，等用户确认。
3. **生成骨架（首选：一条命令）**：
   ```bash
   python3 /var/minis/skills/novel-project/scripts/init_project.py \
     "/var/minis/mounts/小说/<书名>" \
     --title "书名" --genre "流派" --platform "平台" --hero "男主名"
   ```
   脚本会复制全部 113 个文件、把 `{{书名}}` 等占位符替换成实际值，最后打印「还需手工填哪些占位符」。
   - 加 `--dry-run` 可先看会做什么，不写盘。
   - 目标目录非空时脚本会拒绝，需显式 `--force`（防止覆盖已有书稿）。
   - **若 python3 不可用**：改用 `shell_execute` 执行
     `cp -r /var/minis/skills/novel-project/template/. "/var/minis/mounts/小说/<书名>/"`，
     再逐文件替换占位符（会很慢，仅作兜底）。
4. **填占位符**：把 `{{书名}}` `{{流派}}` `{{平台}}` `{{男主名}}` `{{角色名}}` 等替换成真实值。**只替换占位符，不改规则文字**。
5. **初始化进度**：在 `006_进度.md` 的 S0 写"新书立项，待定第一章"，不要编造进度。
6. **报告**：列出实际创建的目录与文件数，指出哪些文件还是空模板等用户后续填。

## 二、日常写作（按库的规矩）

每次开工，严格按这个顺序：

1. **只读两样**：`项目导引/001_总路由.md`（去哪找）+ `项目中枢/006_进度.md` 的 S0（写到哪、下一章是什么）。
2. **定向取文**：按总路由的派工表进对应目录，读该目录的 `000__子路由.md`；不要整库乱翻。
3. **选规则**：精修/改稿/检查 → 读 `项目中枢/文章精修规则/061_规则调用路由.md`，按"本轮唯一主问题"选**一份** 062—083；写新章 → `项目中枢/写文规则/012_场景卡_写新章.md`。
4. **出方案**：先给本轮要做什么、改哪里、为什么，等用户拍板。
5. **执行**：只做已批准的范围。
6. **交付两件套**：优化后稿页 + 对照页（`scripts/make_diff.py 基线.txt 优化稿.txt --out 输出.html`）。写新章按四件：稿子/对照页/P3 数值/改动清单。
7. **三同步**：改完同步 `003_项目目录.md`、`006_进度.md`、相关文件卡；剧情有变再同步 `剧情记忆/`；改完 `rg` 扫旧串确认零残留。

## 三、库维护（免疫系统）

- **变更日志**：动了库的结构（增删移文件、改规则、改编号）→ 立刻在 `数据库维护/056_变更日志.md` 补一条（涉及/改法/原因/备份/是否拍板）。"是否拍板"必须如实填。
- **体检**：按 `数据库维护/057_度量.md` 四指标（周新增≤5、孤儿=0、死链=0、检索跳数≤3）扫描，结果写 `数据库维护/体检/{{日期}}_体检.md`，趋势表补一行。
- **退役**：作废文件不删，加 `_废弃_` 前缀移入 `数据库维护/退役归档/`，并在变更日志记一条。
- **唯一事实源**：同一事实只在一个文件写全文，别处一律引用（详见 `数据库维护/055_约束.md`）。

## 五、检索与对照工具

```bash
python3 scripts/project_read.py plan <文件...>            # 读前预检：大小/切块数
python3 scripts/project_read.py search <目录> "<正则>"     # 递归检索，只出命中行
python3 scripts/project_read.py chunk <文件> <输出目录>    # 大文件切块
python3 scripts/make_diff.py 基线.txt 优化稿.txt --title "标题" --out 对照.html
```

大文件（>30KB 卷纲/细纲）**禁止整份读**，用 search 精确取章行。

## 六、命名与格式红线

- 正文：`第NNN章：标题.txt`（三位补零 + **全角冒号**）
- 顶层目录：`NN_名称`，不跳号
- 活跃文件：`NNN_名称.md`（全库连续序号）
- 每个文件夹必须有 `000__子路由.md` 门牌
- 每个活跃文件开头必须有【文件卡】：作用 / 何时用 / 上游 / 下游
- 退役文件：`_废弃_` 前缀 + 移入退役归档
